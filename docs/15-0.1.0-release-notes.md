# SwiftLLM 0.1.0 Release Notes

## Audience

SwiftLLM 0.1.0 is for Swift app developers building local-first or explicit-provider language model features on Apple platforms.

The package is still pre-`1.0`. APIs are usable, tested, and documented, but some surfaces remain incubating while real apps pressure-test them.

## Highlights

- Core provider-neutral `LLMClient`, request, response, streaming, tool, schema, metadata, capability, and router primitives.
- Foundation Models wrapper with availability checks, token counting, prewarming, generation, typed guided generation, native tool wrappers, and error normalization behind SDK gates.
- OpenAI Responses and Anthropic Messages adapters with injectable transports and streaming tests.
- Context pipeline with token budgets, chunking, transcript chunks, context packing, local RAG, citations, and `LLMContextCompiler`.
- Structured generation primitives with evidence, validation, repair, fallback, and workflow integration.
- Evaluation and diagnostics with prompt reports, structured assertions, fallback matrices, run metrics, local debug bundles, and redacted `LLMRunReceipt` records.
- Endpoint registry and routing plans for local-first and cloud-allowed fallback ladders.
- WWDC26 readiness types for Private Cloud Compute execution targets, quota status, reasoning effort, dynamic context hints, and token accounting.
- Public package polish: Apache-2.0 license, security policy, contribution guide, API stability docs, roadmap, and release process.

## Known Limitations

- OS 27 Foundation Models symbols are not imported yet. PCC and provider-package support are represented by provider-neutral readiness types until the SDK is installed.
- DocC coverage is not yet complete.
- The showcase app is intentionally minimal.
- External provider adapters require app-owned credential storage.
- The package does not persist prompts, transcripts, responses, API keys, or debug bundles by default.

## Migration Notes

This is the first public release. No migration is required.

During `0.x`, source-breaking changes can happen between minor versions when the public shape needs correction. Breaking changes should be documented in `CHANGELOG.md`.
